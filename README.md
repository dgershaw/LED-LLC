# Light Efficient Design website (test copy)

A preview of the new Light Efficient Design, RemPhos and Solera website, published with GitHub Pages so it can be shared without a Claude login.

- Every page is generated by `tools/build.py` from `data/`, `content/` and the templates in `tools/templates/`. After every push, the "Build and publish" GitHub Action builds the sandbox and the live site and publishes them to GitHub Pages; built pages are not kept in the repository.
- `TEST_COPY` marks this as the test copy: pages carry a `noindex` tag and `robots.txt` blocks crawlers, so it stays out of search results. Remove that file at go-live.
- Part numbers and specifications come from the 2026 Full Product Catalog and the spec sheets supplied so far.

## Sandbox, live site and the administration portal

- Every edit and upload lands on the **sandbox** first: https://dgershaw.github.io/LED-LLC/sandbox/ (the `main` branch), rebuilt a few minutes after each save.
- The **live site** (the root, built from the `live` branch) only changes when someone clicks **Approve and publish to live** under *Actions* in the admin page. The approval is recorded in that person's name (`.github/workflows/approve.yml`).
- The **administration portal** at https://dgershaw.github.io/LED-LLC/admin/ lists every change with who made it and when, what is still waiting on the sandbox, and every published version with its approver (`tools/portal.py`, built from the repository's history by `.github/workflows/deploy.yml`).
- Changes made through Claude are committed in the name of the person who asked for them (Claude is the committer), so the portal shows "David, through Claude".
- **Undo a change** (under *Actions*, with the change id shown next to the change on the portal) reverses that one change on the sandbox; the undo waits for approval like any other change (`.github/workflows/undo.yml`). A change that a later change built on cannot be undone automatically.
- The portal has four tabs: **Changes** (each edit with the old and new wording side by side and a link to the page on the sandbox), **Sandbox vs live** (the pages and files that differ right now, from the two builds), **Documents** (every spec sheet, instruction sheet, sell sheet, case study and IES file by product, with what is missing and what is newer on the sandbox) and **QR codes** (the permanent address of every document, pointing at the final domain, with a downloadable SVG code for print).
- **Roll back the live site** puts the live site back to the version that was live before the current one and records who did it; the sandbox keeps everything, and the next approval publishes it all again (`.github/workflows/roll-back.yml`). Each live version carries a `Snapshot:` line naming the sandbox commit it published.

## The admin page

Sign in at https://app.pagescms.org and open this repository (configured by `.pages.yml`). Every save is a commit; the sandbox rebuilds itself and shows the change a few minutes later.

### Product pages

Each product page's title, headline, introduction, key points, "At a glance" features, part-number tables and footnotes can be edited under **Product pages**, in one folder per Products menu category (the files in `content/pages/<category>/`). A page listed under two categories sits in the first one.

- A table row is one line with its cells in column order, separated by `|`. Wrap a value in `**double asterisks**` to mark the factory default. An empty cell is nothing between two `|` marks.
- Photos, downloads, the LBI configurator and the layout of the spec-sheet-led pages are set in the generator, not on the admin page.

### Spec sheets, instructions, IES files and case studies

- **Every document has one permanent address** that never changes, whatever folder it sits in and whatever its version: `docs/<file name>` for documents (for example `docs/LED-8086_Instructions.pdf`) and `ies/<part number>/<file name>` for IES files. Use these in QR codes and printed material. Each rebuild copies the newest version there, so a new revision replaces what the address serves.
- Each kind of file has one folder per Products menu category and, inside it, one folder per product, for example `Spec sheets › LED Lamps › Shoe Box and Wall Pack`. IES files go one level deeper, in a folder named after the part number. The site finds a file by its name in any folder, so moving a file never breaks a link.
- To post a newer version of a document, upload it under the same name with a version or date added: `RP-LBI-Spec_Sheet V2.pdf`, `LBI-G2-Spec-Sheet-rev3.pdf` or `LBI-G2-Spec-Sheet-2026-10-12.pdf`. Every link to that document then opens the newest one. The older version can stay as a record or be deleted.
- Recognized endings: `V2`, `v2`, `ver 2`, `version 2`, `rev3`, `revision 3`, or a date (`2026-10-12`, `10.12.26`, `20261012`), after a space, dash, underscore or dot. A higher version wins; with dates, the latest date wins.
- Uploading a second file under exactly the same name saves it as `name-1.pdf`, which no page links to, so always add a version or date (or delete the old file first).
- A brand-new document (not a new version of one already on the site) is stored right away but appears on a page only once Claude links it. Ask in the project thread.
